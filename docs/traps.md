## СВОД ЛОВУШЕК

**Pixi v8 (dll/pixi.min.js 8.19):**
- Text/Graphics/Sprite по умолчанию eventMode **'auto' = перехватывают
  клики** (Container — 'passive'). Надпись поверх кнопки съедает pointertap:
  на всех текстах-оверлеях `eventMode="none"`, обработчики — на контейнере
  (всплытие ловит детей) или на спрайте под текстом. ОБРАТНО: если клики
  нужны на контейнере — НЕ ставить eventMode="none" на спрайт-лицо карты
  внутри (карта награды перестала кликаться — точка).
- `Container` НЕ имеет свойства `userData` — создаётся присваиванием
  `c.userData = {...}` (обращение `c.userData.x = …` падает).
- `getLocalBounds()` на свежесозданных Text/Graphics врёт (до рендера) —
  высоту скролл-контента задавать ЯВНО из построителя.
- `AnimatedSprite(anims.wait, false)` — автовоспроизведение остаётся
  системе персонажей (true = двойной прогон).
- После `root.destroy({children:true})` ссылки на детей остаются «живыми»
  объектами, но внутрь у них null: вызов `.clear()` у такого Graphics —
  «Cannot read properties of null (reading 'clear')». Обнулять ссылки
  (dragFx и пр.) в exit() и проверять `x.destroyed` перед использованием —
  иначе после первого боя падает каждый drag (карта «зависает» над клеткой
  и блокирует её — выглядело как баг логики призыва).
- Спрайт Text масштабируется scale.x — для вписывания сначала кегль, потом
  сжатие (см. `GAME_UI.fit`).

**Движок zero_engine:**
- `scripts/data/units.js` обязателен в index.html ПЕРЕД engine.js — ядро
  читает глобаль UNIT_CONFIGS в init() (это не только демо-данные).
- Аудио: два канала — `audio.setVolume(0..1)` (sfx) и
  `audio.setMusicVolume(0..1)` (музыка); файлы — `registerFile(имя, url)` +
  `playFile(имя, множитель)` / `music(трек)` (кэш декода ленивый, музыка —
  ключи "music:<имя>"); шаги настроек 0..10 → /10. ЛОВУШКА «звука нет,
  а статус рабочий»: гейн-нода без `connect(ctx.destination)` молчит —
  decoded/playing/volumes при этом честные; искать в channel(), не в
  загрузке.
- События: у Pixi-события (pointerdown на объекте) есть `.global`; у
  DOM-события на window (pointermove/pointerup при перетаскивании) —
  ТОЛЬКО clientX/clientY. Общий обработчик координат обязан принимать
  оба: `e.global ? e.global : { x: e.clientX, y: e.clientY }` — иначе
  drag умирает молча в первом же move (клик при этом работает).
- Игровые скрипты — в конце `<body>` (main.js ищет #boot).

**Харнесс / среда:**
- Headless Chrome `--window-size 1300,760` даёт canvas ~1284×660 — клики
  только через `__GAME.toScreen`, не в лоб.
- `cmd1 && long & sleep; node …` — `&` отрывает ВЕСЬ `cd && cmd`, node
  стартует в старом cwd; инлайн `node -e` с кавычками молча ломается —
  пробы писать файлами в for_work/.
- Скриншоты для анализа: Read уводит в CDN; VLM-пробой по CDN-ссылке с
  обратными слэшами пути иногда падает — надёжнее численный замер масок
  (numpy по цветовым полосам).
- Харнесс: drag мышью начинать от СЕРЕДИНЫ видимой части карты (рука у
  нижнего края, 2/3 размера) — край промахивается хит-тестом; прямая
  замена `B.hand` не перерисовывает слой руки — нужен `select(0); select(0)`
  (layoutHand).
- Драйвер боя в смоуке обязан уметь панель сброса: шкала даёт карты сверх
  лимита 7, и после `endTurn` надо `discardPick(0)`, пока `discarding` —
  иначе ход не уйдёт врагу. Драйвер играет ПАКЕТНО (все карты за один
  eval): поштучные CDP-итерации на длинных боях не успевают.
- **Растущая шкала удлиняет бои до минут** (доход > 10 энергии за ход к
  10-му ходу, армии растут, марш 0.52с/шаг) — органический финиш в смоуке
  не ждём: после ~80 итераций драйвера принудительный `arenaApi._finish(true)`
  (механики к этому моменту уже проверены).
- **Клики по миру подземелья**: цель обязана быть НА ЭКРАНЕ — камера клампится
  по границам карты, дальняя клетка уходит за вьюпорт, CDP-клик мимо canvas
  просто не сработает. Координаты только через `dungeonScene.worldToScreen(x,y)`
  (= `layer.toGlobal`, камера учтена). Перед выбором цели проверять
  проходимость: `dungeonScene.blocked(x,y)` — трассировка ROWS на глаз
  ошибается (у рядов 6–8 проход только в колонке 3).
- **Pixi pointertap требует down и up на ОДНОМ объекте**: микросдвиг мыши
  через границу двух соседних интерактивных зон роняет тап совсем. Для
  полей/сеток — одна зона на всё поле + разбор координат вручную, не зоны
  на каждый элемент (поймали как баг юзера «клик не на всех местах клетки»).
- **Лимит-тесты колоды**: старые проверки сами оставляют копию str5 в
  колоде (после «вернуть базовую копию» дек = 13, не 12) — чистить
  `while (G.deck.includes(id)) remove(id)`, не фиксированным числом remove.
- **Карты расходуются — индексы руки плывут**: после каждого castSpell/
  playCardAt литеральный индекс протухает (дротик ×2: второй каст по
  «старому» индексу 1 промахнулся мимо карты и вернул false каскадом сломав
  следующий блок). Индекс брать заново через `idx(id)` ПЕРЕД каждым
  действием; удалять юниты только `_kill`, не `B.units=[]` (узлы утекут).
- **Шаман в тестах не детерминирован сам по себе**: выбирает случайного
  Гоблина цены ≤ 2 из ВСЕЙ колоды — для проверки конкретной карты чистить
  колоду от прочих дешёвых гоблинов (`B.deck.filter(...)` + push целевой).
- **Атакующие проверки (асассин, лучник) идут через цикл хода**: юнит бьёт
  только маршем в НАЧАЛЕ своего хода, а ассасин 1 hp умирает от любого
  встречного удара в ход врага. Рабочая схема: wipe поля (`__wipeBoard` в
  смоуке — юниты+eHand+eEnergy+traps+brewCasts), асассин на (2,4), цель на
  (2,2) — ход врага сам подводит её на (2,3), удар случится в наш ход.
  Цель с 2 hp собрать заранее: дротик (5→3) + варево №1 (3→2); свежий
  str2 5 hp — для проверки «добивания нет» (5→4). Ниже ассасина цель не
  ставить: вражеский юнит рядом с ним убьёт его в ход врага.
- **`__wipeBoard` сносит узлы, по которым ещё живёт анимация**: после
  wipe+spawn следующий wipe уничтожает узел юнита, чей spawn-punch ещё
  не доиграл — цикл punches в update() падал («scale of null») КАЖДЫЙ
  кадр, сцена глотала в console.error (в `__gameError` не видно!), а всё
  что в update ПОСЛЕ цикла (Пробел, Esc) переставало работать — тест
  «Пробел завершает ход» падал при зелёных соседях. Лечится guard-ами
  `x.node.destroyed → splice/continue` в циклах punches/floats (у moves
  такой стоял изначально). Урок: тихий console.error scenes.js — первый
  подозреваемый, если «половина update не работает».
- **KeyboardEvent-dispatch из CDP может приземлиться в микро-окно** между
  чтением `wasPressed` и endFrame (флаг живёт один кадр) — одиночный

- **Watchdog runtest.sh: grep-паттерн конца теста НЕ должен встречаться в
  текстах ассертов.** Голое слово «конец» в паттерне убивало живой тест на

- **Пересчёт экран↔дизайн — через `ctx.ui.worldTransform`** (a/d/tx/ty —
